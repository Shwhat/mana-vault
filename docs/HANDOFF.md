# Mana Vault handoff

Last updated: 2026-11-20, version 0.13.1.

## Project

Mana Vault is Devon's self-hosted Magic: The Gathering collection and deck manager (repository Shwhat/mana-vault). It runs as one Docker container (Node.js 22, Fastify, SQLite) and serves a React interface for desktop browsers and phones. Version 0.1.0 rebuilt the interface in the OpenSchem design style (program-design-guide skill, "look and shell" adoption), added sign-in, per-account preferences, undo, the About guide and Dockhand-ready deployment. Version 0.2.0 added multiple collections per account, set completion, bulk editing, per-account ownership of collections and decks, sending (copy, share, transfer) with an Inbox, and deck rename and delete. Version 0.3.0 added prices and values, statistics, deck ownership, wishlists, the trade list and trade calculator, copy details (finish, condition, language, trade count), filter tags, the binder layout and flavor name matching. The 0.3.0 features came from a comparison with AeroEagle/mtg-collection-viewer. Version 0.4.0 rebuilt the camera scanner as a continuous, ManaBox-style live scanner with a scanned list. Version 0.5.0 added the Android app (Capacitor around the same interface) with device sign-in, offline use and sync, phone text recognition and Inbox notifications. Version 0.6.0 linked deck cards to collection copies, added proxies and copy details, import and export windows for seven formats, a ManaBox-style scanner with settings and a printing picker, the card page with rulings, a ribbon-only menu with right-click menus, and the phone Home screen. Version 0.7.0 added the Moxfield-style deck builder (Quick add, Edit as text, four views, groups, tags, maybeboard, format checks, playtest, description, history, tokens), the shared collection and deck switcher, the Grid collection layout, and layout fixes from Devon's screenshots. Version 0.8.0 added saved trades (two-column builder, complete with undo, trading between accounts with counter-offers, wishlist matches, public trade binder), card search views (Grid, Binder, List) with paging and owned counts, filters that follow the open view, All collections, the deck header and Add tab, one picker everywhere, ribbon cleanup and scanner fixes (outline and light). Version 0.9.0 added Proxies (a print list kept on the server, sheet settings with a page preview, PDF, MakePlayingCards and MPC Autofill exports, adding printed cards as proxies), the card maker (custom cards in custom sets, saved to the card database for every account), change printing for deck cards and collection copies, adding to the collection or deck selected last, the Decks panel grouped by format with values, right-click menus on collections and decks, `*F*` and `*E*` marks in deck lists, and card database updates that skip bad records. Version 0.10.0 added a finish for every deck card and finish buttons in the printing chooser, so deck cards and collection copies can switch to their foil or etched version. Version 0.11.0 refined card tracking between decks and collections: exact-printing links from Edit as text and imports, Link owned copies, Owned and Other version owned marks with Switch, deck cards that follow their copies' printing and finish, a choice to keep a deck's version when a copy changes, How many to change, Upgrade wanted, finish badges everywhere, Remove how many and Reduce to 1, Add buttons with finishes that name the destination, and Target and Adding here marks. Version 0.12.0 added the admin role and Administration (first-run Setup, Accounts, Sign-up with invite codes, Card database, Pictures, Storage and backups, Devices, Security, Server, Activity), card pictures kept on the server, the full Scryfall data offline (Art and Oracle tags, raw records, unofficial languages), price history, grouped card search, one Add to name button with the printing chooser, picture stacks with finish lines, special foils and many new filters. Version 0.13.0 made one click on a collection or deck pick where cards go (a double click opens it), added Sort to every card search with Best match first, removed the trade buttons and T and G keys outside Trade, replaced prices and text lines on card pictures with pips, added zone buttons that show one zone and set the add zone, added Add deck to collection, and removed Ctrl+N. Version 0.13.1 made card search faster.

## Rules

- Do not build or change the program until Devon says "build it". Settle the specification first with questions. Since 0.11.0, "build it" means build, push and merge (Devon, 2026-11-20).
- Before building, review the enabled skills and state which apply (program-design-guide, program-about-guide, docker-server-setup at minimum; dataviz for charts). Load each one that applies.
- Do not commit or push until asked. Do not remind Devon about uncommitted work.
- A change to how cards look or what they can do goes to every place the same thing appears (collection List, Binder and Grid, All collections, card search, deck List, Text, Stacks and Grid, the Deck list panel, the Card panel and card page, trade lines, the scanned list, proxies), not only the view Devon mentions. Use one shared component or helper so the places cannot drift apart.
- Never use em dashes anywhere (code, comments, docs, interface text). A static test enforces this.
- Answer questions simply and directly, without extra unrequested actions.
- Keep a task list while building, update the README feature list and keep the keyboard shortcut list current (README, About guide page 20 Settings and shortcuts, `SHORTCUTS` in `actions.tsx`, key handling in `main.tsx`).
- Every update ships the server and the Android app together. Attach a debug APK to each build until the app is closer to finished. The `Android app` workflow builds it for every pull request and push to main (artifact `mana-vault-X.Y.Z-debug`; pushes to main also replace the `debug` pre-release on the releases page with it), signed with the shared debug key `apps/android/android/app/debug-shared.p12` so debug builds install over each other. The workspace cannot reach Maven Central, so take the APK from the CI run.
- Update this handoff (here and in the claude.ai manavault project, identical) with every build.
- Raise the version in every place with each delivered build: `package.json`, `apps/server/package.json`, `apps/web/package.json`, `apps/android/package.json` and `package-lock.json` (run `npm install --package-lock-only`). Patch for fixes, minor for features, major only when Devon says so. A static test checks they match.
- Every pull request that changes what the app does, or the rules it follows, also updates the About guide: the affected pages, Capabilities, and a new entry in the release notes. It also raises the version. The version is shown in the guide.
- Every change gets tests; `npm run test:all` must pass before delivery. Where Playwright cannot download its browser, run it with an installed Chrome: `PW_CHANNEL=chrome npm run test:all`.
- Deployment follows the docker-server-setup skill: Dockhand only, no Watchtower, absolute data path, UID 65532, no cloudflared or reverse proxy in the stack.

## Decisions (0.13.0 pick and open, search sorting, pips, zone views, Add deck to collection)

- Asked by Devon after 0.12.0; agreed in chat and Devon said "build it". Devon's choices: phones also use double tap to open; both You give and You get buttons and the T and G keys go (Add to trade binder, that is Mark for trade, stays); Add deck to collection lets the person choose missing cards only or every card; the zone buttons get an All button.
- Pick or open: `components/PickOpen.tsx` `pickOrOpen(key, pick, open)` counts a second click on the same row within `DOUBLE_CLICK_MS` (450) as open, so mouse and touch behave alike (no reliance on `dblclick` in the WebView). Enter opens, Space picks. Used by the Collections and Decks panel rows and switcher rows (All collections opens on one click). Store `targetCollection(id)` sets `targetCollection` and `addTo: collection`; `targetDeck(id)` opens the deck quietly (so `store.deck` changes, which also changes a deck shown in the deck view) and sets `addTo: deck`. Both flash "Adding to name". Switcher rows show Adding here; the list stays open after a pick.
- Search sort: `SEARCH_SORTS` and `SearchSort` in types.ts (client) and card-search.ts (server, `searchOrder`, `plainWords`). `/api/cards?sort=` (400 for an unknown sort) and `currency=` for price sorts; rows are aliased `x` in both the grouped and plain queries. Best match: exact name, flavor name or front face (`name // ...`) first, then names starting with the plain words, then names holding every word, then the rest, each by name. Owned first counts copies of the oracle card. Pref `searchSort` per scope (`cards`, `deckAdd`, `tradeGive`, `tradeGet`). `SortPicker` in CardResults.tsx; `useViewSearch` takes the scope. The You give search is local and sorted by `sortFound` (`search-sort.ts`, the same rules); the Android offline search (`android/catalog.ts`) collects all matches and sorts with `sortFound` when a sort or search words are given.
- Trade: actions `trade.give` and `trade.get`, their shortcut list entries, the T and G keys, the Card panel You get button and the Add to trade menu items (search results, card page, collection entries) are removed. `giveEntry` and `getCard` stay in trade-state for the Trade view.
- Pips: `CountPip` and `FinishPip` (REGULAR pip, `.badge.regular`) in CardMarks.tsx. Deck `Picture` (Grid and Stacks) always carries the count, finish badges, Missing (Missing N when only some), Upgrade wanted and owned marks; Grid shows lines only when a printing has more than one finish in the zone. Collection `Stack` carries the count and `CopyPips` (finish, condition code, language code, Proxy, T for trade) and shows lines only for more than one kind of copy. The Total line and `sl-price` are gone (`.sline` has two columns). Search pictures show `OwnedPips` (OWNED, FOIL, ETCHED counts) on the picture instead of the `.resowned` text line; `.pocketprice` is gone. List views keep prices.
- Zones: pref `deckZoneView` (`all` or a zone). `setZone` in actions.tsx sets both `zone` (All sets main) and `deckZoneView`; action `zone.all`; Z cycles All, Commander, Main, Sideboard, Maybe. `ZONE_BUTTONS` in `zones.ts`; `ZoneButtons` in DeckView.tsx is used above the deck's cards (`.deckzones`) and in the Deck list panel (group name "Zone"). The zone list beside Quick add and ZONE in the status bar change only `zone`. Tokens show only with All.
- Add deck to collection: `POST /api/decks/:deckId/add-to-collection { collectionId, mode: "missing" | "all" }` in decks.ts adds NM English copies in each deck card's printing and finish (maybeboard left out), links each missing card to the new copies with `addLink`, lowers wishlists, logs the deck history, and returns `{ added, linked, before, after, wishlist }`. Wishlists are refused (400). Store `addDeckToCollection` makes one undo step (restoreDeck, then setCounts before, then wishes). Dialog `addDeckToCollectionDialog` in ItemMenus.tsx (deck's collection or the target collection first); action `deck.toCollection` (Decks ribbon Build group, the Add tab bar beside Edit as text, deck right-click menus).
- Ctrl+N is removed from `main.tsx`, `SHORTCUTS` and the New deck action key.

## Decisions (0.13.1 faster card search)

- Reported by Devon after 0.13.0: card search loaded slowly. Measured on 110,000 synthetic printings: the Best match sort itself added only 10 to 15 percent; most of the time was the grouped search from 0.12.0, which put whole card rows through the window step and read the table a second time for the total. Devon said "fix it".
- Grouped `/api/cards`: the `ranked` step keeps only `pid`, `pick` and `printings`; `picked` adds `COUNT(*) OVER ()` as `matches`, which becomes the total (a separate count runs only when the page is empty); the page's full rows are joined from `cards x` last. Broad searches went from about 630 ms to 220 to 280 ms, narrow ones from about 220 ms to 100 ms.
- Owned first: `searchOrder` returns a `with` step (`owned AS MATERIALIZED`, the account's copies summed per oracle id once) with `withValues` bound first; the order looks it up per card. From about 300 ms to 70 ms on all printings.
- Not changed: plain words still match names, type lines and rules text with LIKE, which reads every card; a full-text index would be the next step if searches are still slow on the server.

## Decisions (0.12.0 Administration, offline data, pictures, grouped search)

- Agreed with Devon on 2026-11-20 after 0.11.0 screenshots; Devon said "build it". Scope as listed in the 0.12.0 release notes. Devon plans Windows exe, Linux and Docker releases later, so server folders (pictures, backups) are settings with environment variable overrides, not Docker-only paths.
- Admin role: `users.is_admin` (also `disabled`, `must_change`, `last_sign_in_at`). The first account is admin; at start, when no admin exists, the oldest account becomes admin. The last enabled admin can never be removed, turned off or deleted. `/api/catalog/update` is admin only, and the client disables Update card database for others.
- Settings (`settings.ts`, table `server_settings` key to JSON): signup (open, invite, closed), sessionDays, attemptLimit, minPasswordLength, serverName, updateIntervalHours (168), extraLanguages (true), pictureSizes, picturesDir, minFreeGb (10), backupIntervalHours (0, off), backupKeep (7), backupDir, setupDone, pictureEstimates. Environment variables force and lock them (`settingsFromEnvironment`): MANAVAULT_SIGNUP (on and off still accepted), MANAVAULT_CARD_UPDATE_INTERVAL_HOURS (or CARD_UPDATE_INTERVAL_HOURS), MANAVAULT_PICTURES_DIR, MANAVAULT_BACKUP_DIR; MANAVAULT_SECURE_COOKIE only shows as locked. `Settings.set` refuses locked keys with "This setting is set by X". docker-compose.yml now leaves signup, cookie and interval empty so they are managed in Administration, and sets `MANAVAULT_PICTURES_DIR: /pictures` with the second volume `${MANAVAULT_PICTURES_HOST:-/opt/mana-vault/pictures}:/pictures`. Test options `signup` and `addressAttemptLimit` become forced settings.
- The first account can always be created, whatever the sign-up mode. Invite codes (table `invites`) are one-time, uppercase, format ABCDE-FGHJK. Admin-created accounts get a temporary password (`must_change`); the client asks for a new one at sign-in (`forcePasswordChange`).
- Activity (table `activity`, newest 5000 kept): sign-ins, failed sign-ins, account and settings changes, invites, backups, restores.
- Server backups: `VACUUM INTO` `mana-vault-YYYYMMDD-HHMMSS.sqlite` in the backup folder (default `backups` in the data folder), pruned to backupKeep, scheduled check every 10 minutes. Restore writes `<db>.restore` (from the list, or an uploaded file streamed as `application/vnd.sqlite3`, checked for a users table); the server exits 800 ms later (index.ts sets `exitAfterRestore`), Docker restarts it, and `applyPendingRestore` at start keeps the old file as `.before-restore-<stamp>`.
- Pictures (`pictures.ts`): files at `<size>/<front|back>/<x>/<y>/<id>.<ext>` (Scryfall's own path) in the picture folder; table `pictures(path, stamp, bytes)` records the `?stamp` of each so only new or changed pictures download. An `onSend` hook rewrites every `https://cards.scryfall.io/` in JSON replies to `/pictures/`; `GET /pictures/*` (public) sends the file or redirects 302 to Scryfall. `withServerPictures` in api.ts makes `/pictures/` absolute for the Android app. A chosen folder that is missing is never created; a folder without the marker `.mana-vault-pictures` is only adopted when no pictures were recorded, so an empty mount point is never filled. Downloads: batches of 6, a free space check every 120 pictures, pause and resume, queued after each catalog update (`updater.onUpdated`). Estimates: 40 HEAD requests per size, average saved in `pictureEstimates`; rough averages until measured. Move copies, counts, then sets picturesDir and leaves the old folder.
- Catalog extras (`importCatalogExtras`, after the main import): All Cards for unofficial languages (not es fr de it pt ja ko ru zhs zht, and not en), Art Tags and Oracle Tags (bulk entries found by type or name regex because their names were not reachable from the workspace; JSON array, JSONL or `{data}` handled), then `snapshotPrices`. Each part that fails keeps the stored data. New tables: `card_records` (gzip raw JSON), `card_illustrations`, `tags`, `tag_links`, `tag_children`, `price_history` (one row per card per changed day). New cards columns: lang, promo_types, frame_effects, frame, border_color, full_art, keywords, printed_name (comma lists).
- Search words in `card-search.ts`: `is:`/`not:` owned (any printing of the card name), foil, nonfoil, etched, fullart, borderless, showcase, extendedart, promo, variation, or any promo type (surgefoil...); `art:`/`atag:` (recursive through tag_children, joined on illustration ids), `role:`/`function:`/`otag:` (oracle ids); `pow`, `tou`, `year`; `a:`, `kw:`, `frame:`, `border:`, `lang:`. Every printing ordering prefers `lang = 'en'` first.
- Grouped search: `/api/cards?group=1` picks one printing per oracle_id (English, not promo, not variation, newest) with `printings`, and `ownedFinishes` summed over the card name. Pref `searchAllPrintings` turns it off; the trade You get search never groups. Filters that need the database on local scopes (collection, deck, trade give) use `/api/cards/match` id sets through `useServerMatch`.
- Add: `components/AddButtons.tsx` now has one button and `addCard(store, card, target, zone)`, which opens `choosePrinting` titled "Add NAME to TARGET" with the shown printing selected and the Add as foil finish, or adds at once for one printing in one finish. The deck Add tab zone buttons use it; the Add as segment is gone. Panels show only Adding here.
- Stacks: `stacksOf`, `Stack`, `StackLine` in CollectionView (Binder and Grid, All collections); `byPrinting` and `Picture` in DeckView (Grid lines, Stacks compact). Lines split by finish, condition, language and proxy.
- Special foils: `SPECIAL_FOILS`, `specialFoil`, `finishLabel` in types.ts, used by FinishBadge, the printing chooser and stack lines.
- About fix: `.picker.abselect{display:none}` with the narrow-screen override (bug since 0.8.0).
- Price history chart (`views/PriceHistory.tsx`) follows the dataviz skill: one line per finish, 2 px, crosshair tooltip, Show table.
- Note for operators: the first card database update after installing 0.12.0 is needed for tags, special foils, unofficial languages and price history.

## Decisions (0.11.0 card tracking between decks and collections)

- Reported by Devon after 0.10.0: a deck made with Edit as text showed every card as Missing although the copies were in the collection; linking could end up Missing (a link to another printing moved the deck card, and a later Edit as text with the original set line removed it); the foil badge showed only in the List view. Devon said "build, push, merge" and that "build it" means all three from now on.
- Devon's choices: auto-link matches the exact printing and finish only; lines without a set and number stay missing until linked. The deck follows the linked copy (printing and finish). An Upgrade wanted mark (Devon's name for it; not "substitute") keeps a card owned and records the version wanted. Remove asks how many with Reduce to 1 and Remove all; several picked cards: Remove all as before, plus Reduce to 1. Interface text says cards or entries, never rows. All three add target displays (button names, panel marks, status bar), to try out. When a linked collection copy changes printing the person chooses whether the deck follows; No makes the deck card missing with Other version owned and Switch. Change printing asks how many of a stack change. Changes apply everywhere the same thing appears (new rule above).
- Follow-ups to ask Devon after 0.11.0: whether exact-printing auto-link works the way Devon wants, and whether the add target display (button names, Target and Adding here marks, ADDING TO) works as wanted.
- Schema: `deck_cards.finish` is now part of a deck card's identity (unique index `deck_cards_finish_unique` on deck, oracle, printing, zone, finish; `deck_cards_theme_unique` is dropped at start). New columns `want_card_id`, `want_finish`. Every lookup of a deck card by printing and zone also uses the finish (`addDeckCard`, `moveDeckCards`, `alignDeckCard`, zone moves, imports, Edit as text, backups, the phone's offline copy, `restoreDeck` and `writeDeck` in the store).
- `moveDeckCards` (decks.ts) moves some or all cards of a deck card to another printing and finish in the zone, joining an existing deck card; links go with a whole move when asked, the Upgrade wanted mark goes with the cards, and `clearWantIfMet` removes the mark when the card becomes the wanted version. `linkCopies` uses it, so the deck follows each copy linked. `alignDeckCard` (links.ts) follows the copy's finish too, and Copy details finish changes align deck cards.
- `freeVersions` (decks.ts) lists free copies of every printing and finish, the given printing and the deck's collection first; used by `/candidates` and by `GET /api/decks/:id` as `owned` (up to 12) on cards with missing copies (own links not excluded). The client splits them with `ownedVersions` into exact (Owned, link) and other (Other version owned, Switch).
- `linkOwnedCopies(database, deckId, userId, only?)` links exact free copies to missing cards; route `POST /api/decks/:id/link-owned`; `replaceDeck` (with the user id) and `importDecklist` (with the user id) call it for lines that name a set (and for imports a collector number), reporting `linked`. Add to deck in the client links only exact candidates.
- `PUT /api/decks/:id/entries/:entryId/printing` takes `quantity`; links sent must be of the new printing and finish. `PUT .../upgrade { cardId | null, finish }` sets or clears the mark (400 when it is the deck card's own version). `POST /api/collections/:id/printing` takes `decks: "keep"`, which removes the links of changed linked copies (`dropLinks`) instead of moving them.
- Edit as text: a line whose only change is its finish mark keeps the deck card (and tags), drops its links and changes the finish; otherwise a finish is part of the match key.
- Client: `components/CardMarks.tsx` (FinishBadge, UpgradeBadge, wantedLabel, OwnedMarks, linkExact, switchVersionDialog, removeCard, finishName) and `components/AddButtons.tsx` (AddButtons, addMenuItems, finishesOfCard, defaultFinish, addToCollectionIn, addToDeckIn). `choiceDialog` in Dialog.tsx. `choosePrinting` takes `quantity`, `title`, `allowCurrent` and passes the count. `addToCollection` takes a finish code. Search results carry `finishes`. Store: `linkOwnedCopies`, `markUpgrade`, `changeDeckPrinting(..., collectionId?, count?)`; `setDeckQuantity` undo restores the deck snapshot (links too). Library state: `changeCopyPrinting(entry, to, finish, count)` asks about decks, `reducePicked`.
- Actions `deck.linkOwned` (Decks ribbon, Build group) and `reducePicked` (Collection ribbon, Selection group); "Select all rows" became "Select all cards". Status bar `#st-target` reads ADDING TO and switches deck and collection when a deck is open. Panels mark `Target` / `Adding here` (`.target-mark`).
- Backups stay version 5 with optional `want_card_id`, `want_finish` on deck cards and `deck_finish` on links; older backups attach a link to the deck card of its printing and zone, preferring the link's finish.

## Decisions (0.10.0 deck card finishes)

- Asked by Devon after 0.9.0: Change printing offers the foil version; deck cards keep their own finish (Devon chose this over only linking foil copies). Devon said "build it push it merge". Version 0.10.0 (minor, a feature).
- `deck_cards.finish` (0 regular, 1 foil, 2 etched) is a property of the row, not part of its identity: one row per printing and zone as before. A card added to a zone that already has the printing keeps the row's finish (`addDeckCard`). `readDeckFinish` and `finishOffered` (decks.ts) read a finish and check it against `cards.finishes`.
- `PUT /api/decks/:id/entries/:entryId/printing` takes `finish`; the client links free candidates of the new printing in that finish. `POST /api/collections/:id/printing` takes `toFinish`; the copy key's `foil` changes with it (links follow through `moveLinks`). Both refuse a finish the printing is not made in.
- Prices: deck card price, deck summary value and deck statistics use the deck card's finish (`deckFinishPrice` in insights.ts, `cardPrice` in deck-rules.ts), falling back to the printing's other finishes.
- `*F*` and `*E*` set the finish in Quick add (POST `finish`), decklist imports and Edit as text (a line without a mark sets regular; `deckText` writes the marks). Add as foil passes `finish` when cards go to the selected deck. Backups (version 5) carry `finish` on deck cards; deck copies (`copyDeck`) and `alignDeckCard` keep it.
- The printing chooser (`PrintingDialog.tsx`, `finishesOf`) shows a button per finish with its price; the current printing shows "Current: finish". Clicking a row keeps the finish in use when the printing has it.

## Decisions (0.9.0 proxies, card maker, change printing, menus)

- Specification: `docs/SPEC-0.9.0.md` in the claude.ai project. Devon said "build push merge".
- Deck lines: `splitPrinting` (server `deck-import.ts`, client `deck-rules.ts`, same rules) strips trailing `*X*` marks (`*F*` foil, `*E*` etched, others dropped) before reading the set and number; collector numbers may end in a letter, star or dagger. `printingFinder` falls back to set and number when the name does not match. Deck cards have no finish, so the finish only orders Quick add's link candidates (that finish first); Edit as text and imports do not link.
- Card database updates: `importBulkFile` skips a record that fails a check (and unreadable JSONL lines) instead of rolling back; it stores `last_skipped_count` and `last_skipped_names` (50 names) in `catalog_metadata`, returned as `skipped` by `/api/catalog/status` and shown as "N skipped" in the status bar. `default_cards` stays the source. `cards.back_image_url` (front image from `card_faces[1]` when the card has no top-level `image_uris`) arrives with the next update.
- Change printing: deck `PUT /api/decks/:id/entries/:entryId/printing { cardId, links }` removes old links, merges into an existing deck card of the new printing in the zone, links the copies sent; the client fills links from candidates of the new printing in one collection (asks when several). Collection `POST /api/collections/:id/printing { copy key, to, quantity? }` moves copies (trade marks, copy details) to the new printing row, moves links (linked copies last) and `alignDeckCard` (links.ts) splits or moves deck cards so each deck card's links match its printing. Undo for collections calls the route back with the moved count; decks use `restoreDeck`. The chooser is `components/PrintingDialog.tsx` (`/api/cards/:id/printings`).
- Add target: pref `addTo` ("collection" or "deck"). Opening a collection through `store.openCollection` (panel, switcher) sets `targetCollection` and `addTo: collection`; `openDeck` without quiet sets `addTo: deck`. `addToCollection` without an explicit collection and not a proxy goes to `addToDeck` (through `addToDeckRef`) when `addTo` is deck and a deck is open. Panels highlight only the selected one. "Add here" buttons and `.tgt` styles were removed. The scanner's Add to starts on the deck.
- Decks panel: `deckGroups` (Panels.tsx) groups by format in the client `FORMATS` order (casual last); deck summaries carry `value: { usd, eur }` (printing price, regular or else foil or etched, maybeboard left out).
- Menus: `components/ItemMenus.tsx` (`collectionMenu`, `deckMenu`, `renameCollectionDialog`, `renameDeckFor`) on Collections and Decks panel rows and switcher rows. Deck format and Export open the deck quietly first. `renameDeck(name, id?)` and `deleteDeck(deck?)` work on any deck; `exportWindow(store, what, collectionId?)` exports any collection. Deck list panel rows use `cardMenu` from DeckView.
- Custom cards (`apps/server/src/custom.ts`, tables made in `database.ts`): `cards.custom = 1` rows with ids `custom-<uuid>` and oracle ids `custom-oracle-<uuid>`; `custom_cards` (design JSON, picture, back picture, art, back art as blobs, version) and `custom_sets` (owner, symbol) beside a `sets` row with `set_type = 'custom'`. Shared by every account; only the owner edits or deletes. Delete is refused (409) when another account has copies, deck cards or trade lines; otherwise the owner's copies, deck cards, links and trade lines go. `image_url` is `/api/custom/cards/<id>/picture?v=<version>`; pictures and set symbols are public (`CUSTOM_PUBLIC`), like Scryfall images. Legality: every non-casual format `legal` or `not_legal`. Mana value, colors and identity come from the mana cost and text unless sent. `is:custom` in `card-search.ts`. The scanner name index and name matches leave custom cards out. A change writes `catalog_metadata.custom_at`, part of the compact card list stamp and `/api/sync/state` catalog, so phones download the list again.
- Android app: `withServerPictures` in `api.ts` makes `/api/custom/...` addresses absolute in app answers. Images for canvases are always loaded as blobs through `fetchFile` (no tainted canvas, works with the device token).

## Decisions (0.5.0 Android app)

- Specification: `docs/ANDROID-SPEC.md` in the claude.ai project. Devon chose: Capacitor wrapper around the existing interface, full phone parity plus scanning, offline and notifications, server address entered in the app, read and edit offline with server-wins sync, background check every 15 minutes (no Firebase), on-device text recognition (ML Kit), code in `apps/android`, sideloaded APK from GitHub releases. Devon said "build it" without answering the four open points; the proposed defaults were taken: plain http only for home network addresses (with a warning), Android 8.0 minimum (API 26), app name "Mana Vault" with the existing icon, update check against GitHub releases (the repository is public).
- The app always uses the phone shell (`useNarrow() || isApp()`). The bundled interface is served by Capacitor from https://localhost; the server allows that origin (CORS in `mobile.ts`) and accepts `Authorization: Bearer <device token>`. Device tokens are hashed like sessions, have no expiry, are listed in Devices... and removed by Remove, Sign out or a password change on another device.
- Offline: `apps/web/src/android/offline.ts` wraps `request()` in the app. GET answers are kept in IndexedDB (cache store, keyed by URL); offline they come from there, card search, card details and printings from the compact card list (`catalog.ts`). Changes that can wait (collection card add, set, add many, move, rename collection when rules and sets are unchanged, deck card add, change, remove, deck rename, prefs) are applied to the copy and queued; others say "You are offline. This needs a connection to the server." Online changes are also applied to the copy so it stays right if the connection drops.
- Sync (`POST /api/sync`): queued changes are replayed in order through `app.inject` with the caller's headers; each change id is applied once (table `sync_changes`, kept 30 days). Collection PUT and deck PATCH carry the count the phone saw (`base`) and are applied as a difference. 4xx results are listed in Changes not applied; 5xx keeps the queue. After sending, `GET /api/sync/state` (revision that changes with every successful change, new offers, catalog date) decides whether to download the copy again and the card list (`GET /api/catalog/compact`, gzip JSON with an ETag).
- Undo while offline queues the reverse change (the spec said it would remove the queued change; queuing the reverse has the same result).
- Scanning in the app: `readOnPhone` in `recognize.ts` sends one JPEG of the card area to ML Kit and sorts lines by position (`sortLines`). Matching rules moved to `apps/server/src/scan-core.ts`, shared by the server and the phone.
- Native code is Java (the Capacitor template language), not Kotlin as the spec said. Settings in EncryptedSharedPreferences. Notifications: WorkManager periodic work (15 minutes, unmetered when Check only on Wi-Fi), reads `/api/sync/state`, notifies for offers newer than the last one shown; tapping opens the Inbox.
- Left out of 0.5.0 (spec items): share-to-app imports and deep links; a managed image cache with a size setting (images use the WebView cache); background sync of queued changes from the worker (changes are sent when the app runs); offline statistics not opened before.

## Decisions (0.4.0 scanner specification)

- Modeled on ManaBox (screenshots from Devon): live camera, continuous scanning with no capture button, a last-card strip and a scanned list. Built on branch `scanner-0.4.0`, started before 0.3.0 was merged and then rebased onto it.
- Recognition reads the name line and the bottom-left information line (collector number and set code) with Tesseract.js in the browser. Set code plus collector number gives the exact printing when it agrees with the name; otherwise the name is fuzzy-matched on the server (`POST /api/scan/match`), including front faces and flavor names (a flavor name picks the printing that carries it).
- Name-only matches always take the newest printing (regular before promos and variants), or the printing in a set read from the information line. No set lock.
- A name match needs two equal reads in a row; a set and number match needs one. A card in view is counted once; two empty reads mean it left.
- Read modes cycle after a miss and stay while reads find a card: the card's own lines, then overlapping narrow strips around the top and bottom (wide), then strips for a card about 62% of the outline (small). Crops that are mostly dark are inverted (dark title bars). One large crop was tried and fails (empty table hides the text).
- Scanned list kept in localStorage per account (`mana-vault.scan.<userId>`), rows merged by printing and finish. Edit (quantity, finish, printing), remove, Clear (asks), Add a card by name (same fuzzy match), Add to (any collection, wishlist or deck; one undo step; collections through `POST /cards/add` as NM English, foil rows of etched-only printings as etched; decks use the target zone).
- Last card strip: Normal or Foil, printing (opens the edit window), +1. Torch, tap to focus and continuous autofocus where the camera supports them. Scanner settings in prefs: `scanVibrate`, `scanFoil`, `scanCamera`.
- Phone: Scan tab in the bottom bar (Cards, Collection, Decks, Scan, More); the scanner replaces the view. Desktop: large window, camera left and list right.
- OCR files (worker, two core builds, English best_int model) are bundled under `/ocr` by a Vite plugin; no CDN. Choosing a photo was dropped.
- Condition, language and prices are not set or shown by the scanner (agreed before 0.3.0 added copy details).

## Decisions (0.3.0)

Devon said "build all of it now" for the seven proposals without a question round, so these choices were made during the build and can be revisited:

- Prices: Scryfall's usd, usd_foil, usd_etched, eur, eur_foil stored on `cards` at each catalog update; no price history. Currency pref `currency` (usd or eur), never converted. Copy price: regular, foil, etched (falls back to foil); EUR foil price for foil and etched. Normal decks priced at the cheapest printing, Theme decks at the chosen printing.
- Copy key: a collection row is printing + finish (`foil` column 0 regular, 1 foil, 2 etched) + condition (M, NM, LP, MP, HP, DMG) + language (Scryfall code); `trade` is the count for trade (0 to quantity). Old rows become NM English. The API accepts `foil` as a boolean or 0 to 2; condition and language default to NM and en.
- Wishlist: `collections.kind` ('collection' or 'wishlist'), a checkbox in Collection settings. Excluded from owned counts, ownership and the trade list. Wishlist commands use the first owned wishlist, creating one named Wishlist when there is none.
- Deck ownership: copies in owned and shared collections (not wishlists), allocated commander, main, sideboard; any finish counts; copies are not reserved across decks.
- Trade: trade list = rows with trade > 0 in collections the account owns. The trade calculator lives in the browser (store state) until reload; it never changes collections.
- Statistics: computed on the server (`insights.ts`); single accent hue bars (dataviz: magnitude, not identity), Cards or Value measure, hover and focus tooltips; type counts each main type, front face only; curve excludes lands. Collection bars set filter tags.
- Filter tags (`Facets` in the store): set, rarity, color, type, mana value, finish, for trade; client-side, cleared on collection switch. Sort pref `collectionSort`, layout pref `collectionLayout` (list or binder, 9 per page).
- Flavor names: `cards.flavor_name`; search (plain words and `name:`) and both imports match flavor names and the front face of two-faced cards.
- New keys: 4 trade view, W wishlist, E copy details, B binder, Page Up/Down binder pages, T you give, G you get.
- Backup version 3 adds kind and copy details; versions 1 and 2 still restore.

## Decisions (0.2.0 specification)

- Each account owns its collections and decks. Pre-0.2.0 shared data moves to the oldest account (collection named Main collection). Every new account gets an empty Main collection.
- Each physical copy lives in one collection. Add to collection uses a target collection (pref `targetCollection`, key C). Move commands shift copies between collections.
- Collections link to any number of sets (or none). Completion rule chosen per collection: main (numbered up to Scryfall printed_size; without it, numbered non-promo non-variant), all (every printing), names (one of each oracle card, printings from the linked sets only). Finish rule: any, regular, foil, both (one of each); finishes a printing never had are left out of the total. Etched counts as foil (0.3.0).
- Missing view: counts and percent, list with set, rarity and color filters, add from the list, export as text or CSV.
- Bulk editing: Ctrl+click, Shift+click, Ctrl+A, Select mode on phones; remove and move as one undo step.
- Sending: sender picks Copy, Share or Transfer and it stays fixed. The receiver accepts or declines and chooses how it enters their library: new item with a name, or (collections sent as Copy or Transfer) merge into an existing collection; Share accepts with an optional personal display name. Recipients are picked from this server's account list.
- Deck rename and delete are included; members of a shared item can only leave it.

## Decisions (0.1.0 specification)

- Scope: OpenSchem look and shell on the existing React + TypeScript + Vite and Node/Fastify/SQLite stack. Not a rewrite to plain JS or Go.
- Desktop shell on wide screens; phone layout under 900 px (bottom tabs Cards, Collection, Decks, More; sheets; 44 px targets).

- Preferences are per account.
- Undo covers collection and deck card edits by sending the reverse change. Imports, restores, deck creation and catalog updates are not undoable.
- Tests: server unit tests, static checks, and a Playwright browser suite.

## Known limits

- One click on a deck to make it where cards go loads that deck as the open deck, so a deck view that is showing another deck switches to it (the view itself stays). Undo of Add deck to collection with Every card as new copies lowers the counts back; copies added on top by other edits in between are kept.
- Undo of a collection Change printing answered No (keep the deck's version) changes the copies back but does not put the removed deck links back. Undo of a collection count change does not restore links removed by the lower count.

- The Android app has had one camera test on a phone (0.5.0); 0.6.0 was tested in Chromium with a stand-in for the native plugin. ML Kit reading, the camera permission, notifications, the share sheet and the Back button need checking on a phone.
- The app's release signing needs the four `ANDROID_*` repository secrets (README, Android app); without them the tag build fails with a clear message.
- Offline in the app: card search matches names only (no search syntax), prices only for cards opened before, statistics only when opened before.
- The scanner reads English text. Real OCR was checked with synthetic card pictures through Chromium's fake camera (normal, dark title bar, small, large and off-center cards, name-only cards, a sequence of cards); it has not yet been tried on a phone with real cards, foils or sleeves.
- The live camera needs HTTPS or localhost. The OCR files add about 11 MB to the image (about 7 MB is loaded by a browser).
- Sending works only between accounts on the same server. Offers have no expiry.
- Main set needs Scryfall's printed size for each set; it arrives with the first card database update after 0.2.0. Prices and flavor names arrive with the first card database update after 0.3.0.
- Undo history is per page load and reverses by sending the reverse change; a concurrent edit to the same card by someone else is overwritten by an undo.
- Trades work online only (not queued offline in the app). Accepting a trade with another account cannot be undone.
- Imports up to 5 MB and 5,000 rows; backups up to 250 MB.
- Printing proxies and the card maker's mana symbols need the server to reach Scryfall (cards.scryfall.io, svgs.scryfall.io); without it cards print as white cards with names and symbols are drawn circles. Two-faced cards print their back only after the first card database update with 0.9.0.
- MPC Autofill's own XML order files point to images in its online index, so Mana Vault writes a card list instead. The MPC Autofill list format and the MakePlayingCards picture size (822 x 1122) have not been tried with a real order.
- A Scryfall set that later takes the code of a custom set would rename that set on the next update (custom codes are checked only when made).
- Custom card pictures are made in the browser; a card saved from a browser without a font named Georgia uses the system serif.
- The print list saves count changes 400 ms after the last change; a change made just before closing is sent while the page closes.
- Card pictures not downloaded to the server load from Scryfall through it. Scryfall's Art Tags and Oracle Tags bulk file names could not be checked from the workspace (no internet); the importer finds them by type or name, and a missing file only leaves tags empty.
- Whole-server backups include the card database (with raw records) and can be large; keep the number kept small on small drives.
- The server serves the built files registered at startup; restart it after rebuilding the interface (Docker does this on every deploy).
